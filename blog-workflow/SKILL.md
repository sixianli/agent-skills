# Blog workflow

根据使用者选中的 Hugo 博客处理文章。项目目录、域名、作者、分类、语言和发布方式都从目标项目取得；本技能不预设个人站点。

## 选择目标和检查约定

1. 优先使用本次请求提供的博客目录。当前目录同时具有 Hugo 配置和 `content/posts/` 时，可以把它作为目标。
2. 否则读取使用者已选定的项目配置。没有可确定的目标时，询问博客目录；不要猜测其他项目的位置。
3. 检查目标项目的指令、Git 状态、Hugo 配置、已有文章、语言设置、构建脚本和 CI。保留无关修改。
4. 如果项目提供文章规范或 front matter 模板，遵循该规范；没有单独规范时，从 Hugo 配置和现有文章确认约定。
5. 检查脚本、部署命令和翻译工具按该项目的实际配置选择。不要照搬另一站点的字段、语言、账号或路径。

Hugo 配置可以是根目录下的 `hugo.toml`、`hugo.yaml`、`hugo.yml`、`hugo.json` 或对应的 `config.*`，也可以位于 `config/_default/`。只存在 `content/posts/` 不能证明目录是博客根目录。

处理多个文件时用数组或 NUL 分隔的文件列表，保留空格和非 ASCII 文件名。不要把文件名拼接成可执行的 shell 代码。先查看实际差异，再编辑相关文件。

## blog:header

为指定文章补齐目标博客要求的 front matter。

- 从文章和项目配置取得标题、日期、作者、分类、标签和语言；缺少会改变文章含义的内容时向使用者确认。
- 保留现有有效字段，不把另一项目的 front matter 整体写入当前文章。
- 新草稿保持 `draft: true`，直到使用者要求发布。
- 不默认添加原项目路径、会话标识、账户信息或其他用于追溯个人环境的字段。

## blog:rename

按目标博客现有的日期、slug 和语言命名规则重命名指定文章。

- 先确认源文件、目标文件和当前 Git 修改；目标已存在时停止，避免覆盖。
- 检查文章内部链接、资源路径、翻译组和永久链接。更改已发布 URL 时遵循该博客已有的重定向规则。
- 只重命名本次选中的文章及其必要资源，不重新命名整个站点。

## blog:sync

按目标博客配置的语言和翻译组同步指定文章。

- 从 Hugo 配置和文章中的 `translationKey` 或项目等价约定取得语言和对应关系，不预设固定语言组合。
- 原文是事实来源。翻译保留条件、限制、代码、引语和已经确认的结论，不添加未经证实的内容。
- 使用当前会话允许的翻译方式。没有允许的工具或语言目标不明确时，先确认；不要自动切换到外部翻译服务。
- 保留已有译文的人工修改，检查缺失或过期的段落，再更新确实受影响的内容。

## blog:format

按目标项目的约定完成指定文章的格式整理。

1. 检查 front matter、标题层级、链接、代码块、图片路径和排版。
2. 根据本次请求，执行需要的 `blog:header`、`blog:rename` 或 `blog:sync` 步骤。
3. 运行项目已有的文章检查和构建命令，报告实际执行的检查与尚未检查的内容。

格式整理不自动发布文章。

## blog:upload

按本次发布请求准备并发布指定文章。

1. 确认选中的博客、文章、远端分支和项目发布方式。检查暂存区和未提交修改。
2. 完成文章检查、敏感信息检查及项目要求的构建；修复本次文章造成的问题。
3. 检查最终差异，确认正文和资源齐全。根据使用者的发布请求和项目规则提交、推送或调用部署命令。
4. 需要额外授权的发布目标或账号变更，准备好可审查的结果后再请求授权。
5. 以真实远端或部署结果报告状态。仅有本地构建成功时，只报告构建成功。

不要把另一站点的部署账号、分支、域名或命令写进该项目。

## blog:tilian

从当前 Claude Code 或 Codex 会话提炼技术文章，再放入使用者选中的博客。可以从其他项目会话调用，但仍须单独确定博客目录。

### 读取会话

使用 `scripts/thread_transcript.py`。优先采用会话工具或启动环境提供的明确会话位置；否则按脚本支持的查找方式核对当前项目和最近消息。必须确认读到的是本次目标会话，不能只凭最新文件名选中。

导出文件放在本机私有工作目录，不放入将要共享的仓库。用会话中的目标、决定、已观察到的行为和验证结果提炼文章；工具原始输出仅作为核实材料。

### 起草文章

- 先确认主题、读者和需要保留的技术细节，再解释机制、过程、取舍和结果。
- 区分实际运行结果、静态代码检查、推断和仍未验证的行为。不要把测试样例写成生产环境事实。
- 使用匿名场景和相对路径。删除个人姓名、邮箱、账户、主机、目录、内部项目名、客户信息、凭据和原始会话标识。
- 文章内容必须独立可读，不要求读者访问原项目或原始聊天记录。
- 保持 `draft: true`。其他 front matter 按目标博客的模板填写。

### 扫描和放置草稿

用目标项目已有的敏感信息检查器；可用时同时运行独立的 `sensitive-information-scan` 技能。规则检查后仍须人工审查背景、截图和叙述中可识别个人或项目的内容。

扫描报告只保留类型和位置，不复制敏感原值。处理发现后重新检查文章及资源；未能读取的文件不能算作检查通过。

`place_draft.py` 检查 Hugo 根目录、`draft: true`、目标边界和文件冲突，再复制草稿。显式指定目标时：

```bash
python3 <skill-dir>/scripts/place_draft.py <draft.md> content/posts/<category>/<post>.md --blog-root "<selected-blog-root>"
```

未传入 `--blog-root` 时只检查当前目录，不能退回到维护者的个人路径。复制成功后独立读取目标文件，确认内容和目标位置，再报告草稿路径。

## blog:help

展示这七个命令的用途、当前选中的博客、已发现的项目检查，以及仍需使用者提供的目标信息。帮助输出中不暴露其他项目或个人环境的信息。
