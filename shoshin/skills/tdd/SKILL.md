# tdd

输入为目标缺陷、预期行为和可用测试路径。先确认最小复现及失败机制；本技能承担回归验证，不代替完整诊断。

1. 选择能够捕获目标缺陷的现有单元、组件或集成检查。已有测试足够则复用；新增测试须观察用户可见契约或副作用，而非复制实现步骤。
2. 在修复前运行，确认失败是目标缺陷，不是依赖缺失、环境污染或错误样例。若已通过，先调查测试是否经过失败路径。
3. 修复已确认机制，再执行相同检查和必要邻近验证。不能通过削弱断言、换掉基线或迎合错误实现制造通过。
4. 若有效红态检查不切实际，说明具体原因，选择真实操作、定向脚本或其他有意义证据。没有失败前证据就明确缺失，不补写虚构的红态。

断言拒绝非法输入且文件未写入，是有效行为检查；不能仅因断言检查“没有发生”就判废。mock 只隔离实际外部边界，不用 mock 自报证明产品。

需要判断 UI、mock 与代理自报的证据范围时，通过发现机制定位 create-verification-skill，仅读取 [证据标准](../create-verification-skill/references/evidence-standards.md)。跨技能链接标识 owner 和资源：先按名称从当前宿主技能清单取得实际路径，再读取指定文件；不假定技能相邻，不因此执行 owner 的完整流程。缺失时报告受影响步骤，不能静默跳过后声称完整完成。

交付测试名/命令、实际失败原因、修复后结果和未验证范围。测试与实现的提交方式遵守当前任务 Git 规则，不要求独立红态提交。
