# Retrospective criteria

## Finding selection

For every candidate, verify the triggering incident against an actual action or artifact. A transcript moment or quote locates the claim; inspect the underlying result where available. Distinguish what was observed from causal inference and missing evidence.

Check whether the implicated skill was used, was visible and applicable but missed, or was unavailable. Use invocation evidence and the contemporaneous catalog where available; today's catalog cannot prove past availability. Route a confirmed missed trigger to the description. If evidence cannot establish the category, retain the uncertainty rather than prescribing a trigger fix.

Read the target skill and relevant references before accepting a body edit. Missing guidance merits new content; ambiguity merits clearer wording; buried guidance merits placement or routing changes. Clear, well-placed guidance that was ignored is an execution issue. Do not add a duplicate rule to disguise it. If no target has a reasonable ownership relationship to the finding, reject that routing or assess whether a distinct skill is justified.

Require a recognizable future condition and a concrete different action supported by the evidence. Reject platitudes and incidental facts that expire with paths, commits or tool versions. Preserve useful technical conventions and successful methods when they generalize; failure is not the only source of learning. Do not impose a number of findings or a universal preference for editing an existing skill over creating a well-scoped new one.

Deduplicate by underlying cause and intended action, not matching wording. Resolve conflicting proposals against evidence; unresolved conflicts remain explicit. Reviewer agreement does not increase evidentiary strength by itself. Give rejected findings a concrete reason such as unsupported attribution, already covered, one-off, stale detail, no action change, or inappropriate owner.

## Mechanism selection

Check whether a clear rule already existed when the error occurred. Ignoring an existing rule is an execution mistake, not a reason to copy it into another skill. Propose a local skill correction when the guidance itself is ambiguous or lacks a critical stopping condition.

If the same class of failure recurs in different contexts, assess whether types, invariants, one source of truth, scripts, or tests can constrain it directly. A mechanism needs an explicit trigger, observable result, and maintenance owner. Adding checks everywhere without those properties creates overhead.

Check existing enforcement before proposing another mechanism. If a suitable check exists but was bypassed, repair its reach or execution rather than add duplicate prose or validators. Separate enforceable constraints from guidance that genuinely requires judgment. Give mechanism proposals an actual integration point and failing/valid-case verification, and keep them separate from skill-text proposals. Deferred work needs an explicit disposition; do not label it filed or implemented without the corresponding action.

Record the impact of one-off environment failures without turning them into universal lessons. Preserve counterevidence and distinguish causality from temporal sequence. If only a summary exists without artifacts, state that evidence is insufficient. Apply proposals within current authorization; do not persist personal memory automatically.
